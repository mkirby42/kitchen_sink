# Kitchen Sink — requirements

Company product. Patients find therapists; therapists publish profiles people can actually evaluate. We are past the hackathon freeze: **shipped is the floor, not the ceiling.** If you add or change product behavior, update this file.

## Product

Patients filter therapists by must-have tags. Therapists publish a readable profile (photo, an intro video or a voice prompt, tags, rates, conversation cards, contact).

The current app does **not** book sessions or broker intros. Those are on the backlog, not forbidden.

The default recovery email uses PKCE, and that browser holds the code-verifier cookie; another browser cannot finish the default link. `supabase/templates/recovery.html` uses `token_hash` so a link also works from another device once that template is the one Auth sends.
13. **Client accounts are for reviews only** — Sign up or sign in on a therapist profile to leave a review. The client profile stores the login email and the name `Patient`. It does not store phone, about, photo, video, voice, tags, location, or feedback, and it cannot upload a photo, video, or voice prompt. Find does not attach a search to that account. `20260928131234_client_review_accounts_only.sql`.
14. **Admin view switcher** — A signed-in admin can preview Admin, Therapist, or Client from a header control. The same control stays on profile, join, and password pages so they can switch back. The choice is the `ks_view` cookie until they change it. Non-admins never see the control. Therapist view uses therapist nav (My profile when they have one, Sign out, Referrals when that profile is published, no Uploads, Reviews, or Analytics). Find hides unlisted profiles and the admin-only badge. My profile still opens that owner's page. Client view uses the public nav plus Sign out. Find shows only a public listing, and a hidden profile — including the admin's own — reads as not found. Uploads, Drafts, the review queue, and analytics render only in Admin view. The cookie does not change `role`, RLS, or admin RPCs. It can only hide admin-only rows. Profile Edit and Delete follow the preview: hidden in Client view, own profile only in Therapist view, every profile in Admin view.
15. **Start a therapist draft** — Homepage and `/for-therapists` take a name, email, and 1–8 public profile links. Nothing is fetched from those links. The request is stored on `profile_starts` and emailed to `chrislo5240@gmail.com` with the same Resend setup as join feedback. A saved request keeps the form and opens a confirmation dialog titled “You're in.” (“Request submitted”, the confirmation, and Got it). A failed request leaves the fields in place and shows the error. `/admin/starts` lists requests. Start draft creates a login for that email (server-only `SUPABASE_SERVICE_ROLE_KEY`) and a therapist profile with `listed` false and `published` false. That shell may exist before licenses, rates, and cards only while `profile_starts.status` is `drafting` or `ready` and `listed` is false. Do not treat every unlisted or unpublished row as one of these drafts. An admin fills it at `/join?edit=1&for={id}` with Save as draft only and returns to Drafts. Edit on the profile page and Edit profile on Uploads stay `/join?edit=1&profile={id}` and save with `admin_save_therapist_profile` (does not change `role` or `listed`; on this draft it also cannot set `published`). Email them when it's ready: a password link plus sign-in. Signing in opens the editor. They use the same Save as draft and Publish profile buttons as any other draft. Publish profile saves the profile, then `publish_started_profile` sets `published` and `listed` and moves the request to `published`. That is the only way that draft becomes listed. Until then it is off public Find, the sitemap, and `/t/[id]`. Publish still uses the join rules (a photo plus an intro video or a voice prompt, license, rate, 3–6 cards). Save as draft does not require the photo, intro video, or voice prompt.
16. **Site analytics** — Anonymous page views, Find card clicks (“Get to know”), profile views, and Book a Session / Free Consult clicks. Rows live in `analytics_events`: a random visitor id (local storage), a random session id (session storage), the pathname, and when it applies a therapist id and `book` or `consult`. No IP address, email, account id, query string, or user agent is stored. The browser sends the insert with the anon key and does not wait on it; a failure is ignored. Obvious crawlers and `navigator.webdriver` are skipped. A signed-in admin is not tracked (the layout turns tracking off; an insert that uses that admin's JWT is also rejected). Signed-out visitors and signed-in therapists or clients are tracked, without attaching the account. `/admin/analytics` shows the last 7 or 30 UTC days: page views, visits (sessions), unique visitors, a daily trend, top pages, and per-therapist Find card clicks, profile views, and the two booking buttons. The page checks `role = admin` and Admin view on the server (`adminToolsVisible`). `analytics_dashboard(integer)` is security invoker, executable by signed-in users, and raises unless `private.is_admin()`. Anon can insert only and cannot read. `20261015140030_site_analytics.sql` has to be applied before the page returns numbers. No new env var.
17. **Referral board (therapist side)** — A signed-in therapist with a published profile can post a de-identified referral, see the board, and tap interested. A published profile is the verified check (`listed` and open-to-new-clients are not required). Patients, drafts, and signed-out visitors cannot. An admin in Client view cannot. ## Matching

Access pattern: therapists whose tags **overlap** the patient’s selected tags (match at least one), plus session format and license state when selected. Rank by overlap count, then name. Return `match_count` + `matched_labels` from the same RPC. The phone list card does not show specialty chips or the overlap line. A card with a photo or intro video does not show Takes {plan} or years. A card with no photo and no video shows Takes {plan} and years when those are stored. From `md` up the default grid card does not list specialty chips or the overlap count; it shows one conversation answer, “Takes {insurance}”, and years when stored. One at a time uses that same grid card: no specialty list and no insurance chip cloud. The overlap line is not on that card. The carousel heading is “Therapist {n} of {N} who fit what you told us”. The grid heading is “{N} therapists fit what you told us”.

One RPC or one query. Do not load all therapists and filter in JS. Changing to AND, geo, or pagination should stay one SQL round trip. Find Other is the exception that does not change SQL: `search_therapists` cannot express “label outside this preset list”, and this product does not migrate that function. When `Other` or `Other topic` is selected, Find calls that same RPC once with an empty tag list (format and license state still apply, limit 500, offset 0) and `applyFindOtherMatches` keeps named-tag OR Other rows from that cohort. A directory larger than 500 can miss an Other match that falls outside that cap.

```sql
-- tag OR: therapist tags && selected tags (overlap — match at least one)
-- rank: match_count desc, name asc
-- also: open_to_new_clients, listed, and published (signed-in admin also gets listed = false or published = false)
-- session format: virtual_practice and/or in_person_practice
-- license state: exists licenses.state = selected
```

Indexes (required, this is the performance story):

- `tags (profile_id, kind, label)` unique
- `tags (kind, label, profile_id)` for reverse lookup
- `licenses (therapist_id)`, `licenses (state)`
- `rates (therapist_id)`
- `profile_items (therapist_id, position)` for the first conversation card on a Find card
- partial index on `therapists (profile_id) where open_to_new_clients`
- partial index on `therapists (profile_id) where open_to_new_clients and listed`
- partial index on `therapists (profile_id) where open_to_new_clients and listed and published`
- optional denormalized `therapists.specialty_labels text[]` with GIN if the join is slower in explain. Prefer the array if we touch matching twice.

Return search cards in **one round trip** (join photo URL, credential, years, a few tags). The query may still return min rate, duration, and the sliding scale flag; Find cards do not render them. It also returns `video_key` and the first conversation card by `position`. Cap page size (24). No unbounded select.
