# Kitchen Sink — requirements

Company product. Patients find therapists; therapists publish profiles people can actually evaluate. We are past the hackathon freeze: **shipped is the floor, not the ceiling.** If you add or change product behavior, update this file.

## Product

Patients filter therapists by must-have tags. Therapists publish a readable profile (photo, an intro video or a voice prompt, tags, rates, conversation cards, contact).

The current app does **not** book sessions or broker intros. Those are on the backlog, not forbidden.

3. **Join as a therapist** — Supabase Auth + 4-step onboarding matching the prototype: basic info (name, license number, and state required; education and certificates optional; repeatable state-license rows) → **a profile photo, a short intro video, and an optional voice prompt (Continue does not require any of them; publishing requires a photo plus either the video or a voice prompt — all three are allowed; photo up to 5MB, resized in the browser when larger; video file up to 50MB, or an in-browser recording up to 90 seconds where the browser supports it; voice prompt up to 30 seconds and 8MB, recorded in the browser or uploaded as an audio file, with a title of 1–80 characters)** → practice tags → cards + contact + optional product feedback. A non-empty note is stored on `feedback` and emailed to `chrislo5240@gmail.com` (text, time, `/join`, name, profile email, login email, profile id). Join finishes and opens the profile once that note is saved. The email is sent in the background after the response (one claim, Resend idempotency key, at most once). A failed send is logged on the server and leaves `notified_at` null. The therapist does not see that email or a retry, and opening the profile does not send it. Nothing walks older unsent rows yet. Returning therapists sign in from home (`/join?mode=signin`) and land on their profile. Edit uses the same photo, video, and voice prompt step and does not show the feedback box. Completing join writes `listed` true, `published` true, and `open_to_new_clients` from the form (omitted means open). Find and `/t/[id]` include that profile while it is open, listed, and published. Step 4 of a profile that is not live yet offers **Save as draft**, and **Publish profile** when a photo is attached and either a short intro video or a voice prompt (title plus recording) is attached. Publish is the previous submit: the profile goes live and the feedback note is emailed. Save as draft stores that same complete profile with `published` false, does not email the note, and does not show it on Find or by public link. Save as draft still requires a license, a rate, and 3 cards. It does not require a photo, intro video, or voice prompt. Publish and Save changes require a picture plus either a short intro video or a voice prompt. Without that, a profile that is not live yet only offers Save as draft, and the editor shows “You need a picture, plus a short video or a voice prompt, to publish your profile.” A live profile cannot be saved until that pair is attached, because that save would keep it published. There is no half-filled row. Edit of a published profile offers **Save changes** only. That save writes the live row and cannot set `published` back to false. Edit of a draft offers Save as draft and Publish profile again. An admin editing someone else's existing profile at `/join?edit=1&profile={id}` gets those same buttons (`admin_save_therapist_profile`). That save does not change `role` or `listed` and does not file feedback as them. A draft started from `/admin/starts` is the exception: that admin only gets Save as draft, and only the therapist's Publish profile lists it. An admin replacing their own already-published test profile from Join stays published.

7. **Admin helper upload** — `/admin/media`. An ops admin signs in, picks a therapist (including not open to new clients), and uploads a photo, an intro video, and/or a voice prompt into that therapist's existing storage prefix. Same buckets, mime types, and size limits as join. Photo and video still go through `admin_set_therapist_media`. A voice prompt writes `voice_key` and `voice_prompt` through `admin_set_therapist_voice` (a blank key clears both). This stays the backup when the therapist's browser cannot resize a photo, record a video, or record a voice prompt. No shared ops password is seeded. 8. **Discoverability** — `/robots.txt` allows search crawlers and these AI user-agents: GPTBot, OAI-SearchBot, ChatGPT-User, ClaudeBot, Claude-SearchBot, Claude-User, PerplexityBot, Perplexity-User, Google-Extended. It disallows `/admin` and `/referrals`. `/sitemap.xml` lists `/`, `/find`, `/join`, and therapists who are open to new clients, published, and listed. `/llms.txt` is a plain-language summary of the product. Public pages set a canonical URL on `https://kitchen-sink-tau.vercel.app` (override with `SITE_URL`).
9. **Delete a therapist profile** — On the profile page, Delete asks in plain language (no typed phrase) and then removes the profile. The signed-in therapist can delete only their own. An admin can delete any therapist profile. The editor danger zone under `/join?edit=1` is unchanged for a therapist: it still requires typing `DELETE`. An admin does not get that danger zone. A therapist-role profile is removed by deleting the `profiles` row, which cascades licenses, rates, sliding scale, qualifications, tags, conversation cards, location, feedback, and reviews about them. An admin account that also has a practice keeps the admin profile and role; only the therapist rows (and tags, location, feedback, photo, video, and voice keys) are cleared, and `listed` is stashed so a later Join stays unlisted if it was. Photo, intro video, and voice prompt objects are removed with the Storage API. `auth.users` stays, so a therapist can join again. Patients and other therapists cannot delete someone else's profile. The owner lands on `/profile-deleted`. An admin who deleted someone else lands on `/find`.

11. **Review moderation** — A client or admin sees a personal-health-information warning on review signup and on the review form. Signup asks for email and password only. A new review, including one an admin writes on another profile, is `pending` and is not on the public profile. An admin approves it at `/admin/reviews` or rejects it. Reject, and the author's Remove, hard-delete the row. Nothing archives the rejected text. Reviews have no storage objects. Rows that already existed when this shipped stay `approved`. The form does not collect session length or how long the client saw the therapist; a signed-in save clears those leftover columns.
12. **Forgot password** — Therapist sign-in (`/join?mode=signin`), client review sign-in, and admin sign-in (`/admin/media` and `/admin/reviews`) link to `/forgot-password`. The person enters an email. Supabase Auth sends a reset link. The screen says the same thing whether or not that email has an account. `/reset-password` sets a new password (min 6) for therapist, patient, and admin email/password accounts, then leaves them signed in. Hosted Auth must allow `{origin}/reset-password` as a redirect URL (local `config.toml` already does). The default recovery email works when the link is opened in the same browser; `supabase/templates/recovery.html` uses `token_hash` so a link also works from another device once that template is the one Auth sends.
13. **Client accounts are for reviews only** — Sign up or sign in on a therapist profile to leave a review. The client profile stores the login email and the name `Patient`. It does not store phone, about, photo, video, voice, tags, location, or feedback, and it cannot upload a photo, video, or voice prompt. Find does not attach a search to that account. `20260928131234_client_review_accounts_only.sql`.

The request is stored on `profile_starts` and emailed to `chrislo5240@gmail.com` with the same Resend setup as join feedback. `/admin/starts` lists requests. That shell may exist before licenses, rates, and cards only while `profile_starts.status` is `drafting` or `ready` and `listed` is false. Do not treat every unlisted or unpublished row as one of these drafts. An admin fills it at `/join?edit=1&for={id}` with Save as draft only and returns to Drafts. 16. **Site analytics** — Anonymous page views, Find card clicks (“Get to know”), profile views, and Book a Session / Free Consult clicks. Rows live in `analytics_events`: a random visitor id (local storage), a random session id (session storage), the pathname, and when it applies a therapist id and `book` or `consult`. No IP address, email, account id, query string, or user agent is stored. The browser sends the insert with the anon key and does not wait on it; a failure is ignored. Obvious crawlers and `navigator.webdriver` are skipped. A signed-in admin is not tracked (the layout turns tracking off; an insert that uses that admin's JWT is also rejected). Signed-out visitors and signed-in therapists or clients are tracked, without attaching the account. `/admin/analytics` shows the last 7 or 30 UTC days: page views, visits (sessions), unique visitors, a daily trend, top pages, and per-therapist Find card clicks, profile views, and the two booking buttons. The page checks `role = admin` and Admin view on the server (`adminToolsVisible`). `analytics_dashboard(integer)` is security invoker, executable by signed-in users, and raises unless `private.is_admin()`. Anon can insert only and cannot read. `20261015140030_site_analytics.sql` has to be applied before the page returns numbers. No new env var.
17. **Referral board (therapist side)** — A signed-in therapist with a published profile can post a de-identified referral, see the board, and tap interested. A published profile is the verified check (`listed` and open-to-new-clients are not required). Patients, drafts, and signed-out visitors cannot. An admin in Client view cannot. Posts collect age range, focus areas (the specialty presets only), payment (insurance presets except Cash Pay Only, plus Private pay and Sliding scale), format (telehealth and/or in person), an optional Austin-area neighborhood only when in person, and mornings and/or evenings. No free-text field. The poster must check that the post has no identifying details and that the client knows. Kitchen Sink stores no client name, email, or phone. A post is `pending` until an admin approves it at `/admin/referrals` (approve, reject, or remove a live post). Approval opens it for 7 days. The board shows posted-ago, closes-in, tags (a check on focus, payment, or format that matches the viewer's profile), the interest count, and I'm interested / You're interested. The poster cannot tap interested on their own post. Filters: Matches me (overlap on a focus area or a payment; format alone does not count), All requests, and one chip per payment. `/referrals/mine` lists the poster's posts. They can close a live post early. After the week, or after they close it, Refresh puts the same approved request back on the board for another 7 days (no second approval). Rejected and removed posts cannot be refreshed. When a week ends, the poster gets one email (Resend, same `RESEND_API_KEY` / `RESEND_FROM`) with a refresh link, if `SUPABASE_SERVICE_ROLE_KEY` is set. The button works without that key. "Email these to my client" opens the poster's own email app (`mailto:` with an empty To) with the subject "Therapists who'd be a good fit for you", a short intro, and the selected therapists' names, credentials, fit line, and profile links. Copy share link creates `/referrals/s/{id}` (public profile ids only, no request text, noindex). `20261019160000_referral_board.sql` has to be applied before these pages work. No new env var.

## Matching

Access pattern: therapists whose tags **overlap** the patient’s selected tags (match at least one), plus session format and license state when selected. Rank by overlap count, then name. Return `match_count` + `matched_labels` from the same RPC. From `md` up, cards use the active filters (not a highlight) to list only overlapping specialty and insurance labels; a group with no selected filter shows no chips. The overlap line still reads “3 of 4 tags”. The phone card does not show those chips or that line.

One RPC or one query. Do not load all therapists and filter in JS. Changing to AND, geo, or pagination should stay one SQL round trip.

```sql
-- tag OR: therapist tags && selected tags (overlap — match at least one)
-- rank: match_count desc, name asc
-- also: open_to_new_clients, listed, and published (signed-in admin also gets listed = false or published = false)
-- session format: virtual_practice and/or in_person_practice
-- license state: exists licenses.state = selected
```

Indexes (required, this is the performance story):

- `tags (profile_id, kind, label)` unique
- `tags (kind, label, profile_id)` for reverse lookup
- `licenses (therapist_id)`, `licenses (state)`
- `rates (therapist_id)`
- `profile_items (therapist_id, position)` for the first conversation card on a Find card
- partial index on `therapists (profile_id) where open_to_new_clients`
- partial index on `therapists (profile_id) where open_to_new_clients and listed`
- partial index on `therapists (profile_id) where open_to_new_clients and listed and published`
- optional denormalized `therapists.specialty_labels text[]` with GIN if the join is slower in explain. Prefer the array if we touch matching twice.

Return search cards in **one round trip** (join photo URL, credential, years, a few tags). The query may still return min rate, duration, and the sliding scale flag; Find cards do not render them. It also returns `video_key` and the first conversation card by `position`. Cap page size (24). No unbounded select.

App routes: `/` home, `/find` search, `/t/[id]` profile, `/for-therapists` start-a-draft, `/join` therapist onboarding (auth gated), `/forgot-password` and `/reset-password` (email reset; not indexed), `/profile-deleted` after a therapist deletes their profile, `/admin/starts` profile-start queue (auth + admin role), `/admin/media` ops helper upload (auth + admin role), `/admin/reviews` pending review queue (auth + admin role), `/admin/analytics` anonymous visit and click counts (auth + admin role + Admin view), `/admin/referrals` referral approval queue (auth + admin role + Admin view), `/referrals` board, `/referrals/new`, `/referrals/mine`, `/referrals/[id]` who's interested (published therapist; the interested list is the poster), `/referrals/s/[id]` share link (no request text, noindex). `/matches` redirects home. Unknown URLs, including `/about` and `/feedback`, render the 404 card. `/robots.txt`, `/sitemap.xml`, and `/llms.txt` are public discoverability files. `/referrals` is disallowed in robots.

## Performance

- Match query < 50ms on a small directory; write an `explain analyze` fixture test or SQL comment with the plan.
- Indexes on every FK and every WHERE/JOIN column used by search.
- RLS policies wrap `auth.uid()` in `(select auth.uid())`.
- Images via Supabase public URL; next/image if it is free, skip if it fights Storage. Find shows an intro-video poster and loads the file only after play (`preload="none"`, no `src` until then). The profile hero still plays the same clip. Video via public Storage URL + native `<video>`; no transcoding today.
- No ORM waterfall. Server components fetch; no client waterfall of sequential supabase calls.

## CI / CD

Goal: merge to `main` is production.

1. GitHub Actions: `npm ci`, `tsc`, lint, unit tests (match query + UI tests).
2. Vercel: preview on PR, production on `main`.
3. Migrations live in `supabase/migrations/`. Apply to the linked project from CI or a documented one-liner. Do not click-ops schema.

Secrets: `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY`, and server-only `RESEND_API_KEY` (Join feedback email and profile-start emails). Optional `RESEND_FROM` (verified sender; default is Resend's onboarding address). Server-only `SUPABASE_SERVICE_ROLE_KEY` is required to create the login for a started draft and to build the ready-email link. The rest of the app runs without it. Never commit the service role. Never expose the service role or the Resend key to the browser.

## Demo path

Hosted `/find` lists therapists who completed join, are open to new clients, and are listed. The Maya Chen walkthrough was demo seed data; it is not on the hosted database after the removal migration. A signed-in patient or admin can submit a review on an open, listed profile; it stays pending until an admin approves it. A new therapist can continue the wizard and save a draft without a photo, intro video, or voice prompt. Publishing requires a photo plus either a short intro video or a voice prompt. A published join sets `listed` true and `published` true, so they show up in search while open to new clients. An admin re-join keeps a previous `listed` false (Christine Lo and Matt Kirby stay hidden from the public; a signed-in admin still sees them). CI is green. Match is one indexed query.
